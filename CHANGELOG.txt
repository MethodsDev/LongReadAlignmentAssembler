v0.21.0, August 16, 2026
- NEW: `LRAA --chunk` runs the chunked quantification pipeline from LRAA itself. Chunking previously existed only as `util/misc/run_chunked_quant_pipeline.py`, a separate driver on no routine test path, which is how it came to abort on every chunked run for two releases: at v0.20.0 quant tracking became gzipped and the driver still looked for the uncompressed name, so each chunk that succeeded was reported FAILED. The orchestration now lives in `pylib/ChunkedRun.py` and both routes call it, so the two cannot drift; the script remains as the front end for the parity evaluation, whose `--arm baseline` whole-contig control is a measurement device rather than a mode LRAA has any reason to offer. Chunked mode requires `--quant_only` and `--gtf`, because a chunk sees only the isoforms inside it and discovery across a boundary would produce two partial models of one locus with nothing able to reconcile them. Without `--chunk` LRAA behaves exactly as before, and `--contig`/`--region` are unaffected either way. Verified byte-identical: the merged `quant.expr` and `quant.tracking.gz` from `LRAA --chunk` match the pipeline's own chunked arm exactly.
- FIXED: `--approx_MB_per_cut` and `--approx_MB_per_cut_wiggle_window` did something. Both were accepted, validated and written to `LRAA_Globals.config`, and nothing in LRAA or pylib ever read them -- the only consumer was `select_contig_cut_points.py`, which the chunked driver invoked with explicit values of its own. Passing either to LRAA silently had no effect. They now configure `--chunk`, joined by `--chunk_depth_window`, `--chunk_margin` and `--chunk_work_dir`.
- per-chunk GTF extraction is served from a tabix index instead of a full scan. `load_gtf` read the entire GTF for every chunk, so extraction cost scaled with (chunk count x GTF size) rather than genome size: 50 scans of a 1.49 GB annotation for chr1, projecting to 960 for a whole genome, and 61.6% of the measured extract step. Cut selection already guarantees that a gene overlapping a chunk lies wholly inside it, so the interval itself is enough for emission; the fetch is widened by `margin` because `admissibility_offenders` does not test the interval, it tests each boundary against `cut +/- margin`, and a gene lying entirely OUTSIDE the chunk within that margin still blocks the cut. Fetching the interval alone does not fail on such a gene -- it stops being able to see it, and the check then reports zero offenders where the scan reports one. One parser serves the scan and the fetch, because two would be free to disagree about which lines belong to which gene and the symptom of a disagreement is a silently dropped locus rather than an error. Measured on a 30 MB synthetic annotation: 420 ms per chunk scanning against 6.7 ms fetching, with one 2.1 s build amortised over the run and reused across runs. One index covers both strands; strand is filtered before attribute parsing, so splitting the index by strand measured 1.17x on a mixed-strand chromosome, about 5.6 s across a whole genome, and was not worth doubling the index bookkeeping.
- the source GTF is never modified. The index is written beside it as `<base>.lraa_tabix.gtf.gz`, or under `--gtf_index_cache_dir` when that directory is read-only, and is rebuilt when the GTF's size or mtime changes. A GTF that cannot be indexed falls back to the scan with a warning: losing the index costs time, refusing the run costs more.
- the chunking constants have one definition each. `depth_window` existed as four independent copies across `LRAA`, the pipeline driver, `select_contig_cut_points.py` and `normalize_bam_by_strand.py`; `grid_origin` as three; `margin` and `random_seed` as two each. All happened to agree, and a divergence would not have surfaced as a mismatch -- the values are baked into the stage-2 cut token, so one copy moving turns a stale cache entry into a HIT that reuses the old cut geometry under a token asserting the new parameters. Each is now `LRAA_Globals.config["chunk_*"]` with one consumer, and a test fails if a literal is reintroduced.
- FIXED: `--show_full_usage_info` aborted with `ValueError: unsupported format character 'm'`. A literal `%` in the help text for `--stream_reads_rescue_unassigned_to_targets` was read as a format specifier by argparse's default-value interpolation, so the full option list -- the only place the majority of LRAA's flags are documented -- could not be printed at all. Present since v0.20.1.

v0.20.1, August 15, 2026
- NEW: `--stream_reads_rescue_unassigned` lets `--stream_reads` run under `--quant_read_assignment_mode rescue_unassigned`, which it previously refused outright. Rescue was batch-shaped -- collect a read-name set, write a transcript FASTA, shell out to the minimap2 CLI -- so a streaming pass could not perform it for reads the first pass never saw. The streaming path instead holds a resident minimap2 index per contig/strand through `mappy` and aligns each candidate as it arrives, against the same local transcript models the batch path builds, with the same acceptance filtering and the same projection back through `read_path_mapper`. The candidate population is identical, not merely comparable: the three gated sites -- extractor `low_perID` discards, spacer paths, and reads with no graph path -- select the same reads in both modes, verified as read-name SETS rather than counts on ONT chr20, 14,455 of 120,370 records, zero on either side of the difference, under two different splice graphs. Both paths then rescue the same 6 reads to the same transcripts, fractions agreeing to 1e-5. Opt-in and off by default; without the flag the refusal stands, and it now names only the two modes it still cannot serve rather than all non-genome modes. The batch path's fourth candidate category -- reads with a path that matched no target -- is excluded by default behind `--stream_reads_rescue_unassigned_to_targets`, because the two modes measure it over different populations (batch 3,441 against streaming 11,195) and including it would silently rescue 43% more reads than the batch path targets.
- `mappy==2.28` is added to `Docker/Dockerfile.base`, pinned to the minimap2 binary already in the image. mappy is built from the minimap2 sources of its own release and its mapping heuristics change between them, so an unpinned binding would disagree with the batch path for reasons nothing in the output would show. Two invocation-parity gaps are known and measured rather than absorbed: mappy exposes no equivalent of `-f 0`, so it selects mid_occ 63 where the CLI takes 1,000,000, costing hits on 2.0% of reads; and `map()` takes no query name, so the tie-break ordering minimap2 applies to equally scoring hits is absent, moving the primary/supplementary label on 15.75% of reads and changing an acceptance-visible hit on 2.5%.
- three mappy failure modes that produce no error are now refused at index construction, because each yields zero rescues indistinguishable from a corpus with nothing to rescue: a failed load is falsy rather than raising, an index built without sequences answers every query with no hits, and a multi-part index silently exposes only its first part.
- measured on the bundled ONT chr20 corpus, transcriptome rescue recovers 6 reads of 17,897 candidates, 0.034%, in both the batch and streaming paths. The dominant gate is `rescue_unassigned_min_aligned_read_frac` at its default of 0.95, which alone rejects 17,893 of 36,576 hits on chr20+: these are reads whose genome alignment already explains them, retried against a cDNA where 95% of the read must align end to end. That default is unchanged here and the corpus is a poor-quality ONT library, so the rate is reported rather than acted on; it has not been measured on PacBio.

v0.20.0, August 15, 2026
- BREAKING: quant tracking is always written compressed, as `<prefix>.quant.tracking.gz`. Anything reading `*.quant.tracking` by name will not find it. Tracking is the only output that scales with library size -- one row per (read, isoform), about 140 bytes at ~2.2 rows per assigned read -- so a billion-read library implies roughly 0.30 TB uncompressed against 0.05 TB compressed, measured at 5.57x on an ONT chr20 corpus. Compression is unconditional rather than a flag because a format that depends on a setting has to be sniffed by every consumer; the bundled consumers accept either name and the WDL workflows and testing Makefiles are updated. Single-cell tracking consumers now refuse XW-weighted input outright rather than summing sampling weights as if they were read counts.
- NEW: `--stream_reads` splits quantification into two passes so peak memory stops scaling with library size. Pass 1 quantifies the coverage-normalized bam, whose read count is bounded by the depth target rather than by sequencing depth; pass 2 streams the full bam through the resulting assignment table holding no per-read state, writing one tracking row per (read, isoform) as it goes. Reads absent from the normalized bam are resolved by the rules pass 1 would have applied -- the resolver calls into `Quantify` rather than reimplementing a compatibility cascade that is ten ordered tests deep, because a second copy would mis-assign quietly rather than fail. The mode is opt-in and gated: it refuses `--quant_only`, a first-pass bam thinner than the streamed one, `--quant_read_assignment_mode genome`, and anything but `--tag_bam`, and it refuses rather than approximates at fifteen further points inside the streaming pass, among them a path compatible with transcripts from more than one pass-1 component, which cannot be split because pooling would compare theta from two independent normalizations while splitting would assign the read once per component. Accuracy risk that remains, and the reason it is not the default: pass 1 reads a thinned bam, and divergence concentrates by ambiguity rather than by thinning depth -- at the default target of 1000 on ONT chr20, two overlapping MKKS annotations sharing 1,624 of 2,522 reads differed by 394 while the other 1,478 genes agreed to within 0.2.
- coverage normalization now measures depth over the record set the consumer will actually read, through `Util_funcs.quant_discard_reason`, the same retention policy quantification consumes, with the thresholds passed explicitly rather than read from a config this separate process does not share. Counting records the consumer discards measures a coverage level nothing downstream has: it lowers acceptance probability and so inflates every surviving read's sampling weight at that locus. Percent identity bites most often -- 8% of reads on an ONT chr20 bam at the default floor of 80 -- and mapping quality bites hardest when set, because multimapping reads carry MAPQ 0 at exactly the paralogous loci where thinning decisions matter. `SPLICE_GRAPH_NORMALIZATION_METHOD` moves to `cov5`, so every cached normalized bam misses and is rebuilt. Effect on the default path, measured on ONT chr20 quant-only against v0.19.2: junction measurement drops from 5,244 to 4,501 on one strand, and of 5,822 transcripts exactly one moves, by 0.1 reads, for a total shift of -0.0001%. No read changes which transcripts it is compatible with; 0.0755 reads of EM mass are redistributed across 228,273 read-isoform pairs, a median of 0.000001 each.
- EM runs one further E-step at the theta it returns, so the fractions and counts it reports describe the same abundances rather than the abundances of the iteration before. This is also the step the streaming pass reproduces for a read pass 1 never saw, which is what lets the two passes agree; holding the splice graph and the first-pass bam identical and varying only `--stream_reads`, every gene and all 5,822 transcripts agree to 0.0000 reads.

v0.19.2, August 15, 2026
- FIXED: v0.19.1 aborts on any contig carrying roughly a thousand or more identity-bearing alignments, in both discovery and quantification. The percent-identity QC summary interpolated `min_per_id`, a local that the v0.19.1 retention-policy consolidation had replaced with a config read at its two use sites and deleted; an f-string is built before the logging call decides anything, so reaching that branch raised `NameError` regardless of log level. The branch is reached whenever `min_total_alignments_engage_frac_per_id_check` (default 1000) alignments have carried NM or nM, which is most real data and almost no test fixture -- `testing/single_contig` loses both contig/strand jobs to it, in discovery and again under `--quant_only`. The comparison behind it was also inverted, testing the failure fraction against `min_frac_alignments_pass_per_id_check` rather than the pass fraction, so it fired on every healthy library and never on the one it was written for; it now reports the pass fraction against the configured minimum, at warning level rather than debug, since advice to reconsider `--min_per_id` cannot act on a user who never sees it. Still not fatal: a low pass rate can be a deliberate setting for a noisy library.
- FIXED: splice-graph normalization aborts on an alignment that ends past the reference length declared in the BAM header. `util/normalize_bam_by_strand.py` sized each contig's depth array from that length and wrote to it unchecked, so such a record raised `IndexError` in the first of the two passes and took the run with it. Coordinate-remapped BAMs carry these routinely -- 18.1% of the records in the bundled `testing/sep_contigs` corpus overhang their contig, by up to 40 kb -- and every scatter shard of the bundled WDL workflows over that corpus died. Bounding the write by skipping the window would have replaced the crash with a silent normalization failure, because the second pass already skipped and so found no depth for such a pile and retained it whole; the array now grows to cover every window a read occupies, and the second pass raises rather than skips, since after the first has walked the same reads with the same anchor an unaddressable window means the two disagree. The count of overhanging records and the worst overhang are reported once per input. Out-of-order input, which the default per-contig anchor cannot bin and previously resolved against the array tail, corrupting an unrelated locus, is now refused with a diagnostic; the check reads the records rather than the header's `SO`, and is inert under `--window_origin`, where no aligned position can precede the anchor. Cached normalized BAMs are unaffected and `SPLICE_GRAPH_NORMALIZATION_METHOD` is deliberately not bumped: a corpus without overhanging alignments never reaches the growth branch and its normalized records, XW weights included, are byte-identical across the two revisions, while a corpus with them produced no artifact to cache.
- the bundled test suites now fail when the code they exercise fails. `make test_DTU` had been red since exon counts were propagated through single-cell tracking: `--ignore_unspliced` requires a `num_exons` column that its year-old splice-hash fixture predates, so two of six targets aborted. The column is backfilled from the identity `Quantify` writes the hash code by -- a transcript's splice hash code is its own id when monoexonic and a digest of its intron string otherwise -- which is exact for the only consumer, and a test pins the column to that identity so a hand edit cannot filter the wrong rows silently. `make test_wdls` takes its workflows from the working tree and its code from a published image and never compared them, so a checkout that had moved since `:testing` was built reported the drift as whatever it happened to touch; it now refuses to run unless the image's OCI revision label matches HEAD, refuses an image published before that label existed, and warns when tracked files are modified. Two `ont_sep_contigs` recipes piped LRAA into `tee` and therefore reported tee's exit status, passing whenever LRAA crashed. One further directory had asserted nothing since it was created ten months ago, its comparison commented out against a baseline never written and no target recursing into it; it now has both.

v0.19.1, August 14, 2026
- BREAKING: the four multiplicative CPU flags are replaced by one `--cpu_budget` that the parallelism levels divide rather than multiply. `--CPU`, `--num_threads_per_worker`, `--num_parallel_contigs` and `--no_shuffle_parallel_jobs` are removed. The old flags composed by multiplication with no global ceiling: under the chunked orchestrator at concurrency 6 with `--num_parallel_contigs 4` and `--num_threads_per_worker 4`, a run could reach 6 x 4 x 4 = 96 processes on 16 cores, and `LRAA_runner.wdl` requested `numThreadsPerWorker 5 x num_parallel_contigs 3` = fifteen cores from a node whose core count it never consulted. `--cpu_budget` is a hard cap defaulting to `available_cpus()`, so it respects cpusets rather than the machine. Component-level parallelism becomes demand-driven: a worker grant is taken only when a component actually reaches the 150-node threshold and is returned on abnormal termination as well as on completion. Anything scripting LRAA with the removed flags must be updated; the bundled WDL workflows now take the node core count once as `cpu_budget` and their per-level inputs are gone, which is a Terra-visible input change.
- FIXED: de novo quantification could apportion reads across genes that do not share any read. `quantify()` runs three times on one object in the de novo path, either side of degradation pruning and isoform-fraction filtering, and the read-to-transcript assignment map was never rebuilt between calls. Read-sharing components are derived by unioning the genes of every retained entry in that map, and the guard there only skipped genes absent from the current call, so two genes that both still held isoforms stayed eligible to be fused by a multipath left behind by an earlier call. The fusion can only add genes to a component, so theta was normalized across genes that no longer share a read and every isoform fraction in both was depressed. Nothing in the output marked it: the component is well formed, just not the one the current call's reads describe. Affects de novo runs only; `--quant_only` calls `quantify()` once.
- FIXED: `--region` runs silently fabricated short isoforms. The GTF reader filtered by containment per feature row, so a transcript straddling either bound had its inside exons parsed and its outside exons skipped, and the locus came back with fewer exons than the annotation holds -- indistinguishable downstream from a genuine short isoform. An exon-only GTF does this with no row ever crossing the boundary, so no per-row test could detect it. Containment is now applied to a transcript's whole span: a partly-contained transcript is dropped entire, and the count of dropped loci is reported at warning level rather than passing in silence. Transcripts lying wholly outside the window are unaffected. The chunked pipeline was never exposed, for an unrelated reason -- same-strand gene spans block cut placement absolutely -- but any hand-supplied `--region` carried no such guarantee.
- FIXED: `--region` dropped an alignment at every window start. Region bounds arrive 1-based inclusive and were passed straight to `pysam.fetch`, which takes 0-based half-open, so the left edge began one base late while the right edge was correct by accident. Demonstrated on a two-record BAM: reads at 1-based 151-200 and 201-300 fetched for 200-300 returned only the second. Any region-restricted run has been comparing against a window one base narrower than requested.
- FIXED: several caches returned data built under settings the current run did not ask for. Every affected key gains the missing fields, so all warm caches from earlier versions miss and are rebuilt. The splice-graph cache omitted `min_mapping_quality`, which decides which alignments reach the graph at all rather than how the graph is built from them, so two runs differing only in that flag computed one key and the second was served a graph built from alignments its own filter excludes. The pretty-alignment cache omitted eight inputs that shape what it stores, among them `cell_barcode_tag` and `read_umi_tag` -- which compose the read name as `barcode^umi^query_name`, so a collision there relocates a UMI between cells rather than perturbing a count -- plus `min_per_id`, which `--HiFi` raises from 80 to 97, and the identity of the BAM itself, which had been keyed by basename so two samples both called `aligned.bam` shared one extraction. It also had an ordering defect that left entries actively wrong rather than merely stale: `--oversimplify` force-disabled error correction after the cache token was built, so an oversimplify contig wrote uncorrected alignments under a token recording correction as done, and a later corrected run read it as a valid hit.
- the retention policy deciding which alignments quantification uses is now callable rather than inline, as `Util_funcs.quant_discard_reason()`. It was expressed only inside the read-extraction loop, so nothing outside could ask the question. Two callers use it in this release: the extraction loop itself, and the severed-read emission described below, which needs the alignments quantification will actually use rather than a looser stand-in. Discard reasons are unchanged, so per-reason tallies read as before. `util/separate_bam_by_strand.py` deliberately does not consume it and remains a looser structural filter, because the strand split feeds two paths with different thresholds: isoform discovery keeps `min_mapping_quality` permissive so multi-mapping reads can inform the splice graph, while final quantification may raise `min_mapping_quality_for_final_quant`, so a split applying either would pre-drop reads the other path wants.
- work-unit results are published as shard files renamed into place rather than passed through a result queue, which closes two failure modes: a payload silently dropped when a worker exited before its item was read, and a parent left waiting forever when a worker was killed mid-write. Outputs are byte-identical to the queue implementation across 2,116 components.
- NEW: `--severed_reads_bam` on `util/misc/select_contig_cut_points.py` writes the primary alignments a chunk boundary severs, coordinate-sorted and indexed, and the chunked pipeline now emits it by default. Read names alone cannot answer what a severed read was compatible with, because compatibility follows exon blocks and junctions rather than extent, and a coordinate-indexed BAM cannot be searched by name. The scope is recorded in the BAM's own header comments: these are the alignments extraction would retain at the stated thresholds, taken before normalization, so they are a superset of what quantification saw. Zero records proves no read-sharing component was split by a boundary; a nonzero count needs a whole-library normalized BAM to attribute, which the default chunked arm does not produce.
- NEW: `Quantify.get_transcript_id_to_component_id()` and `get_component_id_to_gene_ids()` expose the read-sharing component each transcript was quantified in. Theta is normalized over a component rather than over a gene, so a consumer recomputing a per-read isoform split needs the component to pick the right denominator; renormalizing per gene gives a read compatible with transcripts of two genes in one component a split summing to 2. The accessors raise rather than return an empty mapping when no quantification has completed, since an empty result reads as "no components" and would be acted on.
- the image build scripts derive the checkout from `git rev-parse HEAD` instead of a pinned SHA file, and `Docker/LRAA_CO.txt` is removed. That file had drifted: it named a 0.18.3-era commit while `VERSION.txt` said 0.19.0, so a release build would have published 0.19.0 images containing code from before the release, and pointed `:latest` -- the tag every WDL image default resolves to -- at the same thing. It also shipped inside every image as part of the checkout, where it read like provenance while describing a different commit than the surrounding code. The commit a build used is now recorded in each image as the OCI `org.opencontainers.image.revision` label, readable with `docker inspect`. All three scripts also build and verify every image before pushing any of them, so a failed check no longer leaves the registry holding a partially updated tag set.

v0.19.0, August 14, 2026
- fixed the splice-graph cache returning the assembly graph to the quantification stage. `_compute_splice_graph_cache_entry()` accepted `quant_mode` and never hashed it, so the assembly build and the final-quant build computed the same key from the same contig, BAM, region and config, and the second one loaded the first one's graph. That substitution is unsound: `quant_mode` gates pruning during construction, so the two stages build different graphs deliberately, and `run_transcript_assembly()` declines to pass `prebuilt_splice_graph` even though the parameter exists for exactly that reuse. Traced on a repetitive Arabidopsis locus: key 9fb1e55a4d48 stored by the assembly build with 9 nodes, 10 edges and 7 exon segments, then returned as a cache hit to a build that would have made 6, 5 and 4; all 141 reads then mapped to SPACER paths, were recorded as having no usable genome path, and went to transcriptome rescue with that as the stated reason -- reads denied a genome path they have, not credited with one they lack. Every ref-guided assembly run since splice-graph caching landed was affected. Guide digests added for the PolyA veto exemption incidentally separated the two stages whenever the transcript sets differed, which they do in every ref-guided run, which is why this surfaced only as one test asserting WHY reads needed rescuing. The separation is now intentional; `restrict_splice_type` and the effective `min_mapping_quality` remain absent from the key, real holes for which no run could be produced where they fire.
- BREAKING: alignment intake is now primary non-supplementary only and is not configurable. `--allow_secondary_alignments`, `--no_allow_secondary_alignments`, `--secondary_alignment_mode` and `--no_cross_gene_EM` are removed, along with the secondary-rescue BAM filter, the cross-gene EM correction pass and its `reassign_multigene_tracking_reads.py` utility, and the `*.pre-cross-gene-EM.quant.*` outputs. Measured on a chr20 HG002 BAM, dropping secondaries moves one read of 82,884: the default `heuristic` mode had retained only 77 of 131,098 secondary candidates, so the machinery was already doing almost nothing. The bundled WDL workflows called the removed options and are repaired in the next entry, which lists the workflow outputs that disappear with them.
- BREAKING: the WDL workflows lose thirteen outputs, which is a Terra-visible interface change. From `LRAA_wf`: `secondaryRescueBams`, `secondaryRescueBais`, `secondaryRescueSummaries`, `preCrossGeneEMQuantExpr`, `preCrossGeneEMQuantTracking`. From `LRAA_quant_by_cluster_wf`: `secondary_rescue_bams_by_cluster`, `secondary_rescue_bais_by_cluster`, `secondary_rescue_summaries_by_cluster`, `pre_cross_gene_EM_quant_exprs`, `pre_cross_gene_EM_quant_trackings`. From the `LRAA_runner` sub-workflow: `LRAA_secondary_rescue_bam`, `LRAA_secondary_rescue_bai`, `LRAA_secondary_rescue_summary`, and the two `LRAA_pre_cross_gene_EM_quant_*`. A workspace binding any of these will fail rather than degrade. The `allow_secondary_alignments` input is removed from `LRAA.wdl` and `LRAA_quant_by_cluster.wdl` and from the three Terra example configs, the `filterBamToSecondaryRescue` task and its calls are gone, and `mergeQuantResults` no longer shells out to the deleted cross-gene utility, writing the merged `quant.expr` and `quant.tracking.gz` directly under their final names. Nothing is lost from the results: the correction that pass applied now happens inside quantification, in the read-sharing component EM above. Verified against a purpose-built image, since every published image predates the removal: unmodified workflows fail with `unrecognized arguments: --secondary_alignment_mode heuristic`, the repaired ones run `testing/sirvs` `test_docker` green across all five commands with the direct quant-only run at Pearson 1.000000 over 69 rows. The three single-cell workflows are type-checked only; no fixture in the repository executes them.
- alignments carrying any intron longer than `max_intron_length` are discarded outright, at both the strand split and read ingestion, from one predicate so the two sites cannot drift. This is a change in kind rather than a tightening: the threshold previously pruned only leftmost and rightmost introns and dropped the overlong edge from the graph, while the alignment itself still spanned the full distance and went on welding distant loci into one component. Ingestion is the load-bearing site, because `--no_norm` and `--normalize_max_cov_level 0` skip the split entirely. On chr20 this removes 542 of 320,240 primary alignments, 0.169%, whose offending introns run from 200,698 to 2,556,198 bp with a median of 448,565.
- genes whose transcripts share a compatible read are now quantified in one EM rather than one per gene. A read compatible with transcripts in two overlapping annotated genes was apportioned twice, by two EMs that could not see each other; components are collected by union-find over the compatibility map that read assignment already produced, so there is no extra pass over the BAM and genes sharing no read stay singletons. Reporting stays gene-scoped: `isoform_fraction` remains a transcript's share of its own gene, not of its component. This restores what the removed cross-gene pass computed -- on chr20 it reproduces that pass's per-transcript counts and mass, with 348 reads apportioned across their two genes summing to 1.0 each, none left whole and none split evenly -- and corrects two further cases: the non-EM path had split a shared read equally within each gene so its mass summed above 1, and a shared read had been counted as uniquely assigned in both genes, which it never was.
- a contig-strand can now be quantified in independently normalized chunks and merged, for chromosomes too large to parallelize any other way. Cuts target multiples of `approx_MB_per_cut` (default 10 Mb) and are chosen inside `approx_MB_per_cut_wiggle_window` (default 1 Mb) under three conditions: they land on the depth-window grid, they never fall inside an annotated isoform, and among compliant positions they sever the fewest retained primary alignments; selection is a DP over targets, so it cannot trade a cut away to save reads, and a target with no compliant position is reported rather than skipped. Reads overhanging a boundary are dropped, counted per cut, and named to a file. `--window_origin` replaces the normalizer's implicit anchor on the first aligned base per contig with an explicit absolute origin, so the same locus lands in the same depth window whether normalized whole or inside any chunk, and `--input_is_single_strand` skips the redundant split and merge for orientation-pure input; with neither supplied, behaviour and every checkpoint token are byte-identical to before. Verified on chr20 against an unpartitioned run: 5 cuts per orientation, 0 of 319,698 alignments severed, all eleven `quant.expr` fields exact on 1,480 of 1,480 transcripts with no field excluded, 82,857 tracking keys identical on transcript, weight and fraction, and the twelve chunks partitioning the annotation with every transcript emitted by exactly one chunk.
- removed `correct_bam_alignments.py`, an early stand-alone alignment corrector that had not been able to run for some time: it invoked the normalizer with `--max_cov` and `--workdir`, neither of which that script accepts, so the call failed at argument parsing. Its manual and the tag documentation describing its four output BAMs go with it; nothing imported it.


v0.18.3, August 10, 2026
- fixed `num_total_reads`, the denominator behind every TPM and behind `min_monoexonic_TPM`, depending on the alignment policy applied to the BAM. The count was taken from whatever `_filter_bam_for_secondary_alignment_policy()` returned, so `--secondary_alignment_mode all` counted every record in the input while `heuristic` counted the filtered file, from which that function drops unmapped and supplementary records before considering any secondary alignment. On an SG-NEx ONT cDNA BAM that is ~74% unmapped, the two modes gave 9,480,826 and 2,436,734 for identical input, a 3.89x shift that moved the monoexonic threshold from a ~9.5-read floor to a ~2.4-read floor and quadrupled the number of single-exon models reported. The count is now taken from the original BAM before preprocessing and restricted to genome-mapped reads (`-F 0x904`), so each aligned read contributes once and the value no longer varies with `--secondary_alignment_mode`. The WDL `count_bam` task, which supplies the same value to every shard on the scatter path, applies the identical filter. The cache filename records the counting policy so a `.count` written under the previous semantics is not reused.
- transcriptome rescue now requires at least 95% of a read's length to align to the target transcript (`rescue_unassigned_min_aligned_read_frac`). Percent identity is computed over the aligned portion alone and is blind to clipping, and the pre-existing check that a rescue explain at least as much of the read as its genome alignment applies only to reads that had a genome alignment to begin with; reads with no graph path, which are the bulk of what rescue retries, had nothing bounding how much of the read the target accounted for, so a short stretch of a long read aligning at the identity floor counted as support for the whole isoform. The requirement is aligned length over read length rather than matched bases so that platform error rates do not make it unsatisfiable; mismatches remain bounded by `rescue_unassigned_min_per_id`.
- monoexonic isoforms must now show that their supporting reads describe one molecule rather than a covered region. A single-exon model has no intron chain corroborating it, so reads that tile a span without overlapping could be collapsed into one long transcript; on SG-NEx MCF7 chr17 this produced, among others, a 19,721 bp single-exon model supported by 188 reads of median length 514 bp. Two criteria are added, each disabled by setting it to 0: `min_monoexonic_read_span_peak_frac` (default 0.5) requires that fraction of the supporting reads to mutually overlap at some single base, and `min_monoexonic_adjusted_TPM_ratio` (default 0.2) requires the model's coverage-depth TPM, read bases on the model divided by model length, to reach that fraction of its read-count TPM. The ratio equals the mean fraction of the model an individual read covers, so it is independent of library size and read count and measures agreement rather than abundance; an absolute threshold on the coverage-depth TPM does not substitute, since a long model tiled by many reads still averages several-fold depth.
- novel monoexonic isoforms discovered from single-cell data must now be supported by a minimum number of distinct cells (`min_monoexonic_supporting_cells`, default 5). A monoexonic model has no intron chain corroborating it, so the number of cells backing it is the one independent axis of evidence available: reads drawn entirely from one cell describe an amplification event rather than a transcript the population expresses. Monoexonic models containing a reference model are exempt, novel ones are not, and multi-exonic models are untouched. Bulk input is unaffected, since its read names carry no cell barcode. Cells are those listed by `--cell_list`, written per cluster by the BAM partitioner from the cell-clusters file and passed to that cluster's run; barcodes outside the list are empty droplets or ambient signal and are excluded from a model's supporting-cell count, since ambient RNA spread thinly across many droplets would otherwise look like prevalence. An absolute count rather than a fraction of the cluster: measured across 14 PBMC clusters spanning 122 to 1,506 cells and 71,446 distinct single-exon models, a fraction's stringency swung with roster size, whereas recovery of reference-matching monoexons under a fixed bar was 98% at 3 cells, 92% at 5, 82% at 8 and 73% at 10, against 26,893 single-exon transcripts in all of GENCODE v39.
- the images build from a shared `lraa-base` instead of deriving from each other, so a version bump no longer recompiles Seurat. `lraa-sc` and `lraa-orf` were `FROM lraa-core`, which put their R and TransDecoder layers above core's LRAA checkout; since Docker keys a layer's cache on its parent image id, moving the pinned commit invalidated everything above it and a release that changed nothing but a git SHA took an hour. All three now build from a dependency-only base with the checkout as their final layer: a simulated bump rebuilds all four images in 20 seconds. The pinned commit moved out of the Dockerfiles into `Docker/LRAA_CO.txt` and is passed as a build arg, so one file holds the SHA rather than four that can drift apart.


v0.18.2, August 8, 2026
- matched reconstructed isoforms to final-graph reference paths after removing reference TSS/PolyA nodes, preserved the matching reference IDs across quantification resets, and excluded synthetic reference reads from draft expression estimates.
- fixed the post-assembly draft quantification step to rescue reads against the assembled isoforms being quantified instead of the supplied reference models; the mismatch let reads already assigned to a draft isoform be realigned onto a reference path and counted twice in the read support that drives isoform filtering.
- fixed transcriptome rescue losing its low-percent-identity candidates on an alignment cache hit: the discarded read names are now stored beside the cached alignments and restored when the cache is reused, and a cache lacking that record is re-extracted rather than reported as having no discards. The cache key also covers the extraction flags that determine what gets discarded, and the unrestricted alignment pickle no longer shares a filename with the multi-exon subset.
- fixed transcriptome rescue reading a truncated read sequence when a hard-clipped supplementary record preceded the primary alignment; sequences are now taken only from primary records.
- the final cross-gene EM correction now runs with the configured EM settings rather than the helper script's own defaults: regularization follows `EM_alpha`, and the abundance floor and unique-read fraction are configurable. Both EM passes now share one convergence rule, `EM_convergence_tol`, applied as the L2 change in normalized abundances, and the cross-gene maximization step no longer adds the abundance floor to its update, so the two passes optimize the same objective. Unique-read counting is defined in one place per purpose: reporting requires a whole read (fraction 1.0) in both the per-locus and cross-gene outputs, while isoform filtering counts a read as unique at 0.9995 to tolerate EM rounding.
- per-read `frac_assigned` and `read_weight` values in the quant tracking output now carry six decimals instead of three. The cross-gene correction re-reads those columns as EM weights and re-derives counts for untouched transcripts from them, so the previous rounding both perturbed the model and drifted reported counts.
- fixed a `ZeroDivisionError` in degradation-product pruning: the relative share of a transcript pair was computed before the pair was tested for structural eligibility, so a gene with expression elsewhere that also contained two zero-support models aborted the run. Such a pair is now left out of expression-based pruning, since its relative support is undefined rather than zero.
- annotation-free mitochondrial pseudo-genes emitted under `--oversimplify` are now named `g:<contig>:<strand>:OVSIMP` rather than `g:OVSIMP:<contig>:<strand>`, so they match the single-cell mitochondrial pattern used for `percent.mt`. Previously those pseudo-genes contributed nothing to mitochondrial content and the cell-level mitochondrial filter never fired in annotation-free runs.
- short annotated transcripts are no longer silently dropped during discovery. A multipath component below `min_transcript_length` is retained for assembly when it holds an input-transcript path, and the transcript-length filter exempts an expressed model that contains a reference transcript. Previously such a locus produced no candidate isoform, so its reads matched no isoform at quantification and were discarded without an output row: on the SIRV reference-guided test, the two annotated transcripts under 200 bases (161 and 189 bases) lost all 15 of their reads, which this fix restores to the reported totals. Those totals no longer account for every read in the BAM: the rescue aligned-length floor added later leaves SIRV107's 11 reads and SIRV206's 3 unassigned, neither model being supplied by the half annotation nor reconstructable from reads, so the test pins 537 of 551.
- gene and isoform identifiers are now reproducible across runs. `comp-N` and `iso-M` were position counters over data structures keyed by splice-graph node and multipath objects, which hash by identity, so set iteration order and therefore the numbering varied between processes. Clusters and isoforms are now numbered from genomic structure, with `comp-1` the leftmost locus on the contig and strand, and reclustering sorts its input so gene membership no longer depends on reconstruction order. Component discovery, the final report order, the splice-containment columns of `quant.expr`, and the BED converter are all ordered deterministically as well. On the SIRV reference-guided test, `quant.expr`, `quant.tracking`, the GTF, and the BED are now byte-identical across repeated runs.
- read paths that match no gene in the splice graph are now counted and reported. Such paths were appended to a list that was never read, so their reads left quantification with no output row, no warning, and no rescue attempt; the only trace was the gap between two other counters. The quantification audit now reports `num_paths_unanchored` and `num_read_counts_unanchored`, and a warning names the lost read count when it is nonzero. Reporting only; no assignment behavior changes.
- reference-guided isoform discovery no longer rescues reads that already have a path through the splice graph. Transcriptome rescue drew candidates from two sources: reads with no graph path, and reads that failed to match a rescue target. During discovery the targets are the supplied reference models, so the second source selected precisely the reads that evidence a novel isoform, realigned them against reference cDNA, and projected them back as a second multipath shaped like a reference model. Extracting the reference path then claimed those reads, which zeroed the genuine novel path's score and ended path extraction with the novel model never built. Discovery now rescues only reads with no graph path; the post-assembly quantification callsite is unchanged, where the targets are the models being quantified and the question is the right one. On the SIRV reference-guided test supplying half the annotation, exact recoveries rise from 60 to 67 of 69 and reported reads from 525 to 537, and guided recovery becomes a superset of annotation-free recovery under matched settings.
- the synthetic reads standing in for input transcripts no longer count toward path scores during isoform discovery. Each input transcript is injected as a multipath carrying one `reftranscript:<id>` read, which gives the reference structure a template in the graph; that read was also counted as support, so every supplied model entered path selection with one unit of manufactured evidence that no novel model could have. A model with no real reads therefore scored 1, cleared `min_path_score`, and was selected as a candidate on nothing but its own annotation. Scoring now ignores those reads, so such a path scores zero and is never selected, while a model with real reads competes on exactly its read count. The read itself is retained on the multipath, so it still supplies the template, satisfies the graph's minimum node count, keeps short annotated loci eligible for assembly, and carries provenance. The node-count fallback in path scoring is now reached only when no read IDs exist at all, rather than whenever a score came out zero.
- graph nodes left unrepresented by isoform path extraction are now reported. Extraction stops when the best remaining path falls below `min_path_score`, which can end a component with nodes still awaiting representation and nothing said about them. The summary now separates the two cases: a node supported only by the synthetic read for an input transcript is expected to be left behind, since nothing observed it, while a node carrying real reads means those reads describe a structure no reported transcript covers, and that raises a warning. Reporting only; extraction is unchanged.
- retention of internally primed monoexonic isoforms is now configurable. A 3' end agreeing with a reference annotation argues that a polyA signal is genuine rather than internal priming, and multi-exonic models were already spared on that basis; monoexonic models were filtered unconditionally without consulting the known 3' ends at all. Setting `spare_monoexonic_internal_priming_with_known_3prime` gives monoexonic models the same reprieve. It defaults to False, preserving current behavior, because a monoexonic model carries no intron chain corroborating it and 3' agreement is weaker evidence there.
- removed the `collapse_alt_TSS_and_PolyA` mode. It gated collapsing reconstructed isoforms that share an intron chain but differ at their termini, and, in degradation pruning, subsuming any splice-compatible contained isoform instead of applying the TSS/PolyA eligibility rules. The key defaulted to False and its only hook was commented out, so neither behavior was reachable; the eligibility rules that already ran are now the only path.
- read junctions declined by the splice-motif check are now counted and reported per contig and strand, separating a motif that implies the opposite strand from one that is canonical in neither orientation. The second case previously produced no record at all. A read whose junctions are all declined has no path through the splice graph, so a locus reachable only through such junctions cannot be reconstructed from reads, and that was previously visible only as an unexplained count of reads with no graph path. Annotation-supplied junctions do not pass through this check, so such a locus is still reachable when the model is provided. Reporting only; junction admission is unchanged.
- degradation-product pruning now resolves equal-length models deterministically, on read support. Transcripts were ordered by descending cDNA length, but that sort is stable and `Transcript` hashes by identity, so models of identical length stayed in the arbitrary order their set produced. Terminal variants of one intron chain are exactly that case: each qualifies as the other's degradation product, and the structural tests run before the expression test, so whichever was examined first survived and absorbed its partner. The survivor therefore changed between runs, and could be the worse-supported model. Ties on cDNA length now break on assigned reads and then on structure, so the better-supported model wins; read counts are a stable snapshot, since absorbing transfers multipath evidence rather than assigned counts. On the SIRV reference-guided test this moves one locus, whose terminals now follow the twin carrying 3 reads rather than the one carrying 2.
- transcriptome rescue now declines an alignment that explains less of a read than the read's own genome alignment already does, and no longer refuses to consider a read merely because it has a graph path. The previous guard, which skipped every read that had any path, was too blunt: a read whose true structure contains a microexon is mapped to the genome with the tiny exon emitted as an insertion rather than traversed, so it has a path, that path is wrong, and only realignment against the transcript recovers it. Rescue is additive and never replaces a read's original multipath, so the question that matters is not whether a read has a path but whether the rescue improves on it; explained read bases answer that, while percent identity does not, being measured over the aligned portion and therefore blind to a target that soft-clips its disagreement away. Reads with no usable graph path keep their exemption, since rescue is their only route in and their genome alignment may still look good.
- fixed transcript-merge mode producing an empty GTF. Discovery injects each input transcript as a template read and discounts it from path scoring, so that a model no read supports cannot be selected on its annotation alone. That registration was not scoped to discovery, and merge mode has no real reads at all: its fake reads carry each input model's weight and are the only evidence present, so discounting them scored every path zero and merged nothing. Registration now happens only on the discovery branch. On the merge execution test the two chr19 strands go from 0 transcripts to 297 and 220.
- an input-transcript template now breaks a tie in isoform path selection. A template contributes nothing to a path's score, so it still cannot make an unsupported model selectable; it only settles which of two paths carrying the very same reads is taken. That case is real: a read whose genome alignment misplaces a microexon, emitting it as an insertion rather than traversing it, supports both the path it was misaligned to and the annotated path it is rescued onto, at identical read counts. Whichever was examined first used to win, and since the template stopped counting toward the score there was nothing left to separate them, so a 4-base microexon that earlier releases recovered was lost. On the SIRV reference-guided test the output is byte-identical.
- a rescued read is now represented only by its rescued path. Rescue realigns a read against a target and projects the hit back into the graph, but it did not detach the read from the path it already had, so one read supported two competing structures and a path whose reads had all moved elsewhere kept their support. On the microexon execution test the same 570 reads backed both the misaligned path and the corrected one at identical counts, which is what made them tie. Acceptance has already established that a rescued alignment explains at least as much of the read as its genome alignment, so the original attachment is the one to drop; a path left with no reads is removed. Reads with no usable graph path have nothing to detach. This also removes at the source the duplication behind the earlier draft-quantification double counting, where a read reaching two surviving models was counted on both.
- the `# LRAA version <v>` comment line now heads every key output, not just some of them. The GTF, `quant.expr`, and `quant.tracking` already carried it; the BED and the two `*.pre-cross-gene-EM.quant.*` files did not. The BED is generated from the finished GTF by an external converter, and the pre-correction quant files are moved aside before the cross-gene EM runs, so both bypassed the stamping applied to the final quant outputs. Every reader in the tree already skips leading `#` lines, including the BED converter, the cross-gene EM helper, and the test validators.
- key outputs now record the invocation that produced them, as a second comment line `# LRAA CMD: <argv>` beneath the version line. The command is shell-quoted, so it parses back to the exact argument vector and can be pasted into a shell to reproduce the run. It is the command as given, not the effective configuration: presets such as `--HiFi` and the contents of a `--config_update` file stay implicit. The version line is left byte-identical so the exact-match idempotency guards in the WDL still recognize a stamped file, and every reader in the tree skips all leading `#` lines rather than a fixed count. In sharded WDL runs each shard records its own command; the merged outputs summarize them (see below).
- WDL merged outputs now carry a command header derived from the inputs they were built from. A sharded run has no single command -- each shard names its own split genome, split BAM and `--contig` -- so `util/lraa_merge_header.py` reduces the shard commands to what they agree on, writing one `# LRAA CMD:` line with the arguments that differed marked `<varies>`, followed by `# LRAA merge: <n> inputs; ...; --contig values: ...`. This covers the merged GTF, the merged `quant.expr` and `quant.tracking.gz`, their `pre-cross-gene-EM` counterparts, and the cell-cluster-guided merged GTF and tracking.

It stripped only the first line of each shard, which was the version comment until the command line was added beneath it, so a merged GTF opened by claiming the whole file came from `--contig chr1` and repeated a stale command at every shard boundary. Each shard's entire leading comment block is now dropped in favor of the merged header.

Rescue is on by default, and the only sign that it had been skipped was a warning written to a per-contig log that the run deletes on cleanup, so a run missing the binary reported fewer assigned reads and looked successful: the Docker image shipped without minimap2, and on the SIRV reference-guided test that cost 11 of 548 assigned reads with nothing in the retained output to say so. `LRAA` now checks for the binary immediately after the run configuration is settled -- when rescue is enabled or `--quant_read_assignment_mode` is `transcriptome_only` or `genome_tx_arb` -- and exits before any work is done, naming the setting that requires it; the rescue entry point raises rather than returning empty for callers that bypass the CLI.
